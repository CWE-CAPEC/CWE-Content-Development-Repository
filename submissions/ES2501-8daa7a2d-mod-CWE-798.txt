DEMONSTRATIVE EXAMPLES:

INTRO TEXT:

This code stores a database password in a PHP file.

BAD CODE:
LANGUAGE: PHP

<?php
$db_username = "secretUsername";
$db_password = "secretPassword";
$db_host = "localhost";
$db_name = "exampleDatabase";

// Database connection
$conn = mysqli_connect($db_host, $db_username, $db_password, $db_name);

if (!$conn) 
{
    die("Connection failed: " . mysqli_connect_error());
}
echo "Connected successfully";
?>


EXPLANATORY TEXT:

This code hardcodes the database password directly in a PHP file that
is part of the web application. If the source code is ever exposed
(through other weaknesses such as directory traversal,
misconfiguration, version control leaks, backups, or server
compromise, etc.), the attacker can obtain the password.

GOOD CODE:
LANGUAGE: PHP

We can store the config.php outside the webroot directory.

<?php
// config.php
return [
    'db_username' => 'secretUsername',
    'db_password' => 'secretPassword',
    'db_host'     => 'localhost',
    'db_name'     => 'exampleDatabase',
];

The main script that connect to its config.php file:

<?php
  // Load config
  $config = require DIR . '/../config.php';

  // Create connection
  $conn = new mysqli(
    $config['db_host'],
    $config['db_username'],
    $config['db_password'],
    $config['db_name']
  );

  // Check connection
  if ($conn->connect_error) {
    die("Connection failed: " . $conn->connect_error);
  }
  echo "Connected successfully";
?>

EXPLANATORY TEXT:

Note that this code moves the credentials into a separate
configuration file that can be stored outside the webroot, but it is
not a complete fix. This reduces the risk that the credentials can be
accessed directly, and it makes it easier to manage configuration
separately from code. However, the password is still stored in
plaintext on the server, so filesystem access still exposes the
password.  If an attacker can gain access to the file using a separate
weakness - such as with path traversal or if the configuration file is
checked in to source control - this fix would still be subject to
CWE-260: Password in Configuration File.

For stronger security, using environment variables or a secrets
manager in addition to proper file permissions would be a significant
improvement. A complete solution might require design changes that
would depend on the specific context, environment, and available
protection mechanisms.
