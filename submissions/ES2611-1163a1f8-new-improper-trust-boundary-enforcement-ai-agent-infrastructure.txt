NAME: Improper Trust Boundary Enforcement in AI Agent Infrastructure

DESCRIPTION:

AI/ML agent infrastructure treats data crossing a trust boundary - model
outputs, serialized artifacts, inter-agent messages, or network requests -
as trusted code or configuration, without validation proportional to the
privilege of the operation performed.

Agent systems connect untrusted reasoning engines (language models) to
privileged execution environments (shells, databases, file systems,
browsers) through interfaces that lack authentication, origin validation,
input sanitization, or authorization proportional to the operation's
privilege. Unlike traditional web applications, the exposed endpoints are
designed to execute arbitrary operations (run code, control devices, query
databases) - the weakness is not what they do, but that the trust boundary
between the requester and the execution environment is absent or
insufficient.

This weakness manifests in six recurring patterns across 40+ frameworks
(200,000+ combined GitHub stars):

1. Agent frameworks bind network sockets on all interfaces without
authentication, exposing tool execution to any network peer.
2. ML pipeline tools deserialize model artifacts using formats that permit
arbitrary code execution (pickle, logging.config), with blocklist-based
safety scanners that are structurally incomplete.
3. Model Context Protocol (MCP) servers expose powerful tool operations
over HTTP/SSE without origin validation or DNS rebinding protection.
4. Agent code execution sandboxes use application-layer string-matching
denylists that are bypassable via shell builtins and interpreted languages.
5. SSRF guards trust stdlib IP classification (e.g., Python
ipaddress.is_global) without unwrapping IPv6 transition addresses (NAT64,
6to4) that embed private IPv4 targets.
6. Per-tool authorization has coverage gaps where synthesized or
alternative code paths bypass the authorization check.

The class is distinct from prompt injection (which targets model reasoning)
- ATBV exploits the infrastructure layer and may be exploitable without any
LLM in the loop. Based on empirical analysis of 62 confirmed
vulnerabilities discovered through responsible disclosure (2026).
