SUBMISSION TYPE: Software

NAME: Inconsistent Enforcement of Object-Level Authorization Across Operation Types

DESCRIPTION:

The product enforces an object-level authorization check on some operations
against a resource but not on others, such that an actor who is correctly
denied read access to an object may still perform state-changing operations
on that same object.

Object-level authorization is typically implemented first on retrieval
paths, where the consequence of a gap (data exposure) is well understood
and widely tested. Operations that modify, delete, transfer, or otherwise
change the state of the same object are frequently reached through separate
code paths in which the ownership binding is re-derived independently, or
not derived at all. The result is an enforcement surface that is correct in
one dimension and incomplete in another. Because the read path behaves
correctly, test protocols that verify cross-actor read access return a
clean result, and the gap on the mutation path is not surfaced by that
testing.
In an empirical analysis of 84 confirmed object-level authorization
failures drawn from publicly disclosed reports, this pattern accounted for
over 40% of cases, the single largest family observed. Deletion operations
form a notable subset, since a successful unauthorized deletion produces no
exfiltration signal for monitoring to detect.
